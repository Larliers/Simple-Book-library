## Text Rules 滚动白屏修复（wheel-over-select 误触发全量重建 + 入场动画重播）

### 背景
接手 `Agent-rule/logs/history/HANDOFF-scroll-whiteflash.md` 交接：Text Rules 面板上下滚动时出现「白屏/像整页重载」，此前多轮模型仅列出假设（H1–H5）未定位具体触发扳机。

### 根因（代码级 + 已知浏览器/OS 行为交叉验证）
- Windows 10/11 默认允许「鼠标悬停即可用滚轮改变非活动/未聚焦控件」，对原生 `<select>` 的效果是：**悬停滚轮即可静默改变其选中值并触发 `change`**，无需点击/聚焦（Chromium 与桌面应用一致，QWebEngine 同源）。
- `text_rules.js` 中栏 `buildTrMidCol()` / `buildStepCard()` 把 `source`、类别 (`catSelect`)、类型 (`typeSelect`) 等多个 `<select>` 密集排布在可滚动的 `.tr-col` 内；这些控件的 `change` 监听器原先都调用 `renderTextRulesPanel()`。
- `renderTextRulesPanel()` 每次调用都 `clear(host)` 整块销毁面板并重新创建 `.tr-overlay`/`.tr-host`，而这两个类选择器的 `overlayIn`(160ms)/`modalIn`(180ms) 是**无条件的入场淡入/缩放动画**，任何一次重建都会重播——这正是「白屏/像整页重载」的视觉来源；用户在中栏滚动时鼠标经过某个下拉即可无意间触发，且普通编辑操作（增删步骤等）本身也有同样的闪烁与三栏滚动位置丢失问题。
- 与 handoff 假设 H1（滚动中触发全量重建）、H3（`.tr-col` 缺 `overflow-anchor: none`）吻合，并补上了此前未找到的具体触发链路。

### 修复
- `src/bookhub/ui/web/js/text_rules.js`
  - `ensureTextRulesHost()` 新增 `installTrWheelGuard(host)`：委托监听 `wheel`，事件目标落在 `<select>` 内时 `preventDefault()` 并把 `deltaY` 手动转发给 `.tr-col`/`.tr-drawer-body`，从根上阻止悬停滚轮静默改值。
  - `renderTextRulesPanel()` 拆分：只在 `openTextRulesPanel()` 打开面板时构建一次性外壳（overlay/host/panel/header/footer，带入场动画），随后调用新函数 `renderTrBody()`。
  - `renderTrBody()`：仅清空重建 `.tr-body` 里的三栏内容（`buildTrLeftCol/MidCol/RightCol`），重建前后按列顺序保存/恢复各 `.tr-col` 的 `scrollTop`；不接触 `.tr-overlay`/`.tr-host`，因此不会重播入场动画。
  - 原先所有调用 `renderTextRulesPanel()` 的编辑入口（字段切换、规则/步骤增删移动、source/类别/类型 change、模板应用、预设保存/应用/删除）全部改为 `renderTrBody()`。
- `src/bookhub/ui/web/css/app.css`
  - `.tr-col` 补 `overflow-anchor: none`，对齐 `.content-split` / `virt-spacer` / `.cover-grid` 已验证约束。
  - `.tr-drawer-body` 同样补 `overflow-anchor: none`。
- `src_construction.md`：原位插入更新 `text_rules.js` 与 `app.css` 两条模块说明，反映外壳/局部重建拆分与 wheel 守卫。

### 验证
- `pytest src/tests/test_web_bridge_smoke.py`：本次改动为纯前端 JS/CSS，未触碰 Bridge/Python 层；已运行确认未破坏既有用例（见执行记录）。
- 人工复现步骤（需用户真机确认，当前环境无法驱动内嵌 QWebEngineView 的真实鼠标滚轮事件）：
  1. 打开 Text Rules 面板，光标停在中栏任意下拉框（来源/类别/类型/参数）上滚动滚轮——下拉值不应改变，面板不应闪烁。
  2. 中栏快速上下滚动同时进行「加步骤/删步骤/切类别」等编辑——面板局部更新，无整面板淡入闪烁，左右两栏滚动位置不受影响。
  3. 关闭再重新打开面板——入场动画应正常播放一次（确认外壳一次性动画未被误删）。

### 仍待 / 风险
- 未覆盖 Settings 页等其他原生 `<select>`（收藏/漫画排序等）：同一 Windows/Chromium 悬停滚轮行为理论上也可能在那里复现，但它们的 `change` 处理都是轻量局部更新（不会整页重建/重播动画），且目前无用户反馈，本轮未扩大改动范围；若后续复现可复用同一套 `wheel` 守卫模式快速扩展。
- 未做 handoff 建议里更大的「left/mid/right 三栏独立组件化」架构重写；当前的外壳/body 二分已消除「clear 全量 DOM + 重播入场动画 + 丢三栏滚动位置」这一具体链路，更大重构留作可选后续项。
- 本次修复无法在当前无 GUI 环境下用真实鼠标滚轮驱动内嵌 QWebEngineView 复现/回归验证，请用户在真机按上述步骤确认后反馈。
