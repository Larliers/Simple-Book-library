## 架构决策记录
- **为什么用 `file://` URL 而非裸路径**：标准 URI 格式与后续迁移到远程 HTTP URL 接口一致，同时解决 Windows 路径中文百分号编码问题
- **为什么不新建 `thumbnail_url` 字段**：`thumbnail_path` 语义已扩展为"图片定位符"，保持字段名不变降低迁移成本；DB schema 不变，旧数据无需迁移
- **为什么不在 DB 存 base64**：图片二进制与索引数据解耦，避免 JSON/SQLite 膨胀，符合用户"图片单独上传、书单只存 URL"的核心需求

右键编辑封面功能：右键 → 打开弹窗选图片（upload 接口）→ 返回 URL → 更新 coverUrl。

## 实施内容

### 1. 右键菜单新增「🖼️ 编辑封面…」入口

### 2. _edit_cover() 实现封面编辑完整流程
**文件**: `src/bookhub/ui/pages/library_page.py`
完整流程（对应 JS 注释中的 upload 接口描述）：
1. **文件选择弹窗**（upload 接口入口）：`QFileDialog.getOpenFileName`，过滤常见图片格式
2. **图片转换**：使用 Pillow 将任意格式转为 WebP quality=80，保存到 `img_preview/cover_{hash16}.webp`；Pillow 不可用时降级为原格式拷贝（`shutil.copy2`）
3. **生成 file:// URL**（upload 接口返回值）：`out_path.as_uri()`
4. **更新 DB**（coverUrl update）：`repository.update_book_thumbnail_path(book_id, file_url)`
5. **更新内存 ResourceItem**：`resource.thumbnail_path = file_url`，保证 `render()` 立即生效
6. **刷新 UI**：调用 `self.render()`

### 3. _build_thumbnail_icon() 支持 file:// URL
**文件**: `src/bookhub/ui/pages/library_page.py`
- 原逻辑直接 `Path(item.thumbnail_path)`，无法处理 `file://` URL。
- 新增 `file://` 分支：`urlparse` + `url2pathname`；旧裸路径保持原逻辑（向后兼容）。
- 影响列表视图（list mode）的缩略图图标。

### 4. 文档更新
**文件**: `src_construction.md`

## 架构决策记录
- **为什么用文件选择而非内置裁剪器**：最小实现原则；用户可在外部应用裁剪后再选择。
- **为什么文件名用源路径 MD5 而非时间戳**：同一文件重复编辑时幂等（不产生冗余文件）；时间戳会因多次操作堆积孤儿文件。
- **为什么 Pillow 降级而非强依赖**：Pillow 已在 requirements.txt 中（PyMuPDF 扫描也依赖图像处理），但降级保证在极端环境下功能仍可用（只是不压缩）。
