# BookHub 项目文件结构与架构设计文档

## 一、设计目标

本项目为「个人知识书库管理系统 + 阅读器 + AI扩展平台」，架构需满足：

- 本地桌面软件（无服务依赖）
- 高性能书籍管理（SQLite）
- 可扩展 AI 能力（本地模型 / API）
- 支持用户脚本自动化
- 支持插件化扩展
- 长期可维护

---

## 二、顶层目录结构

```
bookhub/
├── src/              # 核心代码
├── user_data/        # 用户数据（数据库 / 模型 / 缓存）
├── docs/             # 项目文档
├── tools/            # 开发工具
├── app.py            # 启动入口
└── pyproject.toml    # 项目配置
```

---

## 三、核心代码结构（src/bookhub）

```
src/bookhub/
├── ui/               # UI层（PySide6）
├── domain/           # 领域模型
├── services/         # 业务逻辑
├── infrastructure/   # 基础设施
├── scripting/        # 脚本系统
├── plugins/          # 插件系统
├── common/           # 公共工具
└── tests/            # 测试
```

---

## 四、UI层（ui）

```
ui/
├── pages/        # 页面（书库/阅读器/设置等）
├── dialogs/      # 弹窗
├── widgets/      # 组件
├── models/       # UI数据模型
├── delegates/    # 渲染
├── resources/    # 图标/样式
└── viewmodels/   # UI逻辑绑定
```

### 原则
- UI 不直接访问数据库
- UI 不直接调用 AI
- UI 只负责交互和展示

---

## 五、领域层（domain）

```
domain/
├── entities/         # Book / Tag / BookList
├── value_objects/    # Shortcut / TagRule 等
├── repositories/     # 抽象接口
└── events/           # 领域事件
```

### 职责
- 定义“数据是什么”
- 不依赖 UI / DB / API

---

## 六、服务层（services）

```
services/
├── library/
├── tags/
├── booklists/
├── reader/
├── converter/
├── settings/
├── search/
└── automation/
```

### 职责
- 处理业务逻辑
- 所有操作统一入口

示例：

```
UI → Service → Repository → DB
脚本 → Service → DB
AI → Service → DB
```

---

## 七、基础设施层（infrastructure）

```
infrastructure/
├── db/
├── filesystem/
├── logging/
├── config/
├── ai/
├── external/
└── bus/
```

---

## 八、数据库结构（infrastructure/db）

```
db/
├── connection.py     # 统一连接
├── pragmas.py        # SQLite优化
├── migrations/       # 版本迁移
├── schema/           # 表结构定义
├── repositories/     # SQLite实现
└── backup/           # 备份恢复
```

### 设计原则

- 不在 UI 层写 SQL
- 所有 DB 操作走 repository
- 使用 migration 管理版本

---

## 九、AI 模块（infrastructure/ai）

```
ai/
├── providers/     # OpenAI / 本地模型 / Ollama
├── embeddings/    # 向量检索
├── prompts/       # Prompt模板
├── model_runtime/ # 推理封装
└── tools/         # AI工具函数
```

### 说明

- providers：统一接口
- tools：供 Agent 调用
- prompts：独立管理（避免散落代码）

```

├── app.json
├── shortcuts.json
├── ai.json
└── reader.json
```

---

## 十五、关键设计原则

### 1. 分层

```
UI → Service → Domain → Infrastructure
```

### 2. 数据隔离

- src：代码
- user_data：用户数据

### 3. 扩展优先

- AI独立
- Script独立
- Plugin独立

### 4. 可维护性

- 模块清晰
- 低耦合
- 可替换

---

## 十六、总结

本架构支持：

- 高效书库管理
- 自定义 Tag / 书单
- 内置阅读器
- 格式转换能力
- 本地 AI + API
- 自动化脚本系统
- 插件扩展能力

该结构适用于长期演进型桌面应用开发。
